==================================================
PROJECT
==================================================

Flood Forensics is an agentic urban flood investigation and resilience platform.

The system investigates flooding AFTER or DURING an event and answers:

1. What happened?
2. Why did it happen?
3. Has this happened before?
4. What permanent intervention should be made?
5. Did the intervention actually work?
6. What should the city do next?

The core differentiator is:

FLOOD EVENT
→ EVENT RECONSTRUCTION
→ ROOT CAUSE
→ RECURRENCE ANALYSIS
→ PERMANENT FIX
→ FIELD VERIFICATION
→ URBAN RESILIENCE IMPROVEMENT

The product should feel like a professional municipal emergency/intelligence command center, NOT a consumer weather app.

--------------------------------------------------
1. EVENT RECONSTRUCTOR
--------------------------------------------------

Input:
- flood event
- rainfall
- water levels
- citizen reports
- response actions

Output:
- reconstructed timeline
- affected locations
- severity
- evidence
- confidence

Example:

14:00 Rain begins
14:18 Rainfall intensity increases
14:31 Water level critical
14:37 Citizen report
14:42 Road flooded
15:05 Emergency response
16:20 Water recedes

--------------------------------------------------
2. ROOT CAUSE AGENT
--------------------------------------------------

Investigate possible causes:

- excessive rainfall
- drainage blockage
- insufficient capacity
- low elevation
- pump failure
- downstream obstruction
- maintenance failure

Do NOT return a single unexplained answer.

Return ranked causes:

cause
probability/confidence
supporting evidence
contradicting evidence
explanation

Example:

Drain D142 blockage — 71%
Drain capacity — 18%
Pump failure — 7%
Other — 4%

--------------------------------------------------
3. RECURRENCE AGENT
--------------------------------------------------

Find historical events with similar:

- location
- rainfall
- duration
- water level
- drainage conditions
- causes

Calculate a similarity score.

Generate a "Flood DNA" profile:

- rainfall threshold
- critical duration
- common causes
- recurrence count
- average recovery time
- vulnerable infrastructure

--------------------------------------------------
4. PERMANENT FIX AGENT
--------------------------------------------------

Generate 2–3 possible interventions.

For each:

- intervention
- estimated cost
- expected risk reduction
- implementation time
- priority
- confidence

Separate:

IMMEDIATE RESPONSE
from
PERMANENT INTERVENTION

Include cost-vs-impact comparison.

--------------------------------------------------
5. FIELD VERIFICATION AGENT
--------------------------------------------------

Accept before/after inspection images.

Analyze:

- blockage
- debris
- standing water
- drain condition
- visible infrastructure damage

Compare:

before blockage %
after blockage %

Return:

VERIFIED
PARTIALLY VERIFIED
VERIFICATION FAILED

Always allow human override.

--------------------------------------------------
6. URBAN RESILIENCE COMMANDER
--------------------------------------------------

The Commander orchestrates the other agents.

It should NOT invent facts.

It should collect evidence from the agents and produce:

- incident brief
- primary cause
- supporting evidence
- recurrence information
- recommended intervention
- verification status
- resilience score
- confidence

Also provide a natural-language query interface.

Examples:

"Why did J18 flood?"

"Has this happened before?"

"What should we fix first?"

"Which locations have the highest recurrence risk?"
